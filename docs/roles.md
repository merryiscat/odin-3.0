# 역할과 모델

이 프로젝트의 자리·모델·경로 단일 출처. 절차는 docs/protocol.md.
모델명은 여기에만 적는다 — 바뀌면 이 표만 고친다.

> **모델 모드: 페이블 소진(fable-out, 2026-09-18)** — 페이블 주간 한도가 소진돼 pl2 검토자를 오퍼스로 내렸다.
> 검토 방향(Codex 작성 → Claude 검토)은 그대로다.
> 한도가 돌아오면 `ws-model.sh fable-in <프로젝트>`. 쿼터 소진은 Claude Code가 자동으로 모델을 내려 주지 않는다.

| 역할 | 자리 | 에이전트 | 모델 | 쓰는 경로 |
|---|---|---|---|---|
| main 구현·통합 | 원본 체크아웃 | claude | 기본 | 전부. **쓰기는 여기 한 곳뿐** |
| pl 스펙 작성 | 워크트리 `pl` 터미널 1 | codex | `gpt-6-astra` high | `docs/tasks/`만. **스펙 v1·v2 쓸 때만 켠다** — 종량 쿼터 |
| pl2 검토 | 워크트리 `pl` 터미널 2 | claude | `claude-opus-5` | `docs/reviews/`, 스펙의 "검증" 절. 스펙에 1회·산출물에 1회, 그 뒤 `/clear` |

교차 검토는 **작성자 Codex → 검토자 Claude** 방향일 때만 값을 한다. 반대로 붙이면 점수가 떨어진다(protocol 근거).

## 난이도 등급표

차선 판정용이다(protocol 1절). 구현은 등급과 무관하게 main이 한다 — 별도 워커를 띄우지 않는다.

| 등급 | 기준 | 목표 시간 |
|---|---|---|
| S | 되돌리기 쉽다 · 운영 영향 없음 · 요청이 곧 완료 기준 | 5분 |
| M | 여러 파일 · 판단이 조금 필요 · 되돌릴 수 있음 | 15분 |
| L | 운영 환경 · 되돌리기 어려움 · 미지 영역 | 40분 |

## 이름 규칙

- 기획 워크트리 `pl`(주제가 여럿이면 `pl-<주제>`). 브랜치 마지막 세그먼트가 `pl`/`pl-*`면 `.githooks/pre-commit`이 `docs/` 밖 커밋을 막는다
- 스펙 파일 `docs/tasks/T-NNN-<slug>.md`, 검토서 `docs/reviews/T-NNN.review-vN.md`
- 터미널 구분: `pl` 워크트리에서 Codex 터미널은 pl, Claude 터미널은 pl2. 제목이 아니라 명령으로 판별한다

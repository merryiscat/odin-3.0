# state_module — 상태 모듈 (시장 판단)

> 데이터 흐름: **보다 → [판단] → 실행 → 보여주다** 중 **판단(앞부분)**.

## 하는 일
지금 시장이 어떤 국면인지 판단해서 **표(DB)에 쓴다.** 여러 층으로 깊게:
지수 국면 → 시장 구조(폭·주도·테마별 국면) → 자금·심리 → 맥락(환율·간밤 나스닥)
→ 궤적(며칠째·전환) → 예측(다음 국면).

- 옛 오딘의 `market_regime`(지수 6상태·1분 실시간)은 **참고만 — 이식 안 함, 새로 만든다**(2026-09-03 결정).
- **읽기**: `data_pipeline`이 채운 원천 표(`raw_*`, `dim_*`).
- **쓰기**: 국면/상태 표(예: `state_*`). 다음 모듈(`model_module`)이 이 표를 읽는다.

## 확정 설계 — 1층 시장 온도 (2026-09-04 결정)
> ※ 2026-09-12 재편: 모델에 **노출하는 어휘는 "사다리 + 꼬리표"**(아래 "실시간 판별기" 절이 최신).
> 2축(방향×열)은 폐기가 아니라 **내부 계산 단계·근거(metrics)로 유지** — 사다리가 두 축의 조합이다.

**2축 온도계** 방식. 라벨 하나가 아니라 **독립 축 2개를 각자 판정·각자 저장**한다:
- **방향**(추세): 상승 / 횡보 / 하락 (3단계)
- **열**(격렬함): 차분 / 달아오름 / 과열 (3단계)

| | 차분 | 과열 |
|---|---|---|
| 상승 | 건강한 상승 | 과열 상승(꼭지 위험) |
| 하락 | 질질 하락 | 패닉(급락 중) |

- **이름표는 조합에서 파생** — 단 2026-09-12부터 **파생 결과를 저장**한다(아래 "표준화 원칙" 참조).
  "반등 초입" 같은 궤적성 이름표는 궤적 파라미터가 생긴 뒤(하락→상승 전환 N일째).
- 이유: 축별 3단계라 표본 풍부·깜빡임 관리 단순, 모델 마트의 모델이 필요한 축만 읽을 수 있음.
- **재검토 조건**(버린 안: 단일 라벨 4개/6개): 백필 측정에서 두 축이 미래 수익을 각자 못 가르면
  (축 변별력 실패) 단일 라벨 방식 재검토.

### 대상 시장 — 나라×판 2슬롯, 8개 (2026-09-04 결정)
같은 온도계 엔진을 8개 시장에 각자 돌린다(표에 `market` 칸 하나로 구분). **나중에 미장 매매로
확장할 때** 구조 변경 없이 홈 시장만 바꾸면 되게 하는 대비.
| 나라 | 본판("스피") | 성장판("스닥") |
|---|---|---|
| 한국 | KOSPI | KOSDAQ |
| 미국 | S&P500 | 나스닥 종합 |
| 일본 | 닛케이225 | 그로스250(구 마더스) — KIS 제공 확인 필요, 안 되면 TOPIX 계열 대체 |
| 중국 | 상해종합 | ChiNext 창업판 — KIS 제공 확인 필요, 안 되면 심천종합 대체 |
- 홈 시장(지금은 한국 2개)은 모델이 직접 읽고, 나머지 6개는 맥락으로 읽음.
- 갱신: 각 시장의 장중 시간대에 갱신. **1분 실시간은 홈 시장만** — 해외는 지연시세·일봉이면 충분.
- 적재 우선순위: 한국 → 미국 → 일본 → 중국.

### 한국 시장 거래 시간 사실관계 (2026-09-04 확인 — 판정 스케줄의 기준)
개별 종목 주가는 **08:00~20:00** 움직이지만, 공식 코스피·코스닥 지수는 **09:00~15:30만** 산출된다.
| 시간 | 무슨 일 | 지수 |
|---|---|---|
| 08:00~08:50 | NXT 프리마켓(개별 종목 실체결) | 없음 |
| 08:30~09:00 | KRX 시가 동시호가 접수 | 예상지수만 |
| 09:00~15:20 | KRX 정규장 + NXT 메인마켓 | **공식 산출** |
| 15:20~15:30 | KRX 종가 동시호가 → 지수 확정 | 확정 |
| 15:40~20:00 | NXT 애프터마켓 + KRX 시간외(16~18시 단일가) | 없음 |
- **주의(관찰 항목)**: KRX 자체 거래시간 연장이 **2026-09-14 시행 예정**(프리 07:00~07:50, 애프터
  16:00~20:00). 시행되면 주가 움직임 시작이 07:00으로 당겨짐. 지수 산출 시간 확장 여부는 미확인 —
  시행 후 확인해서 판정 스케줄에 반영할 것.
- 설계 함의: 하루는 재료가 다른 3구간 — ① 아침(08:00~09:00, 프리마켓 체결·예상지수·간밤 해외),
  ② 정규장(공식 지수 1분), ③ 저녁(15:40~20:00, 애프터마켓·미 선물). "개장 전 판정" 개념은 폐기.

### 추적 창 — 주가가 움직이는 전체 시간 (2026-09-04 결정)
**08:00~20:00 전체를 추적한다**(KRX 연장 시행되면 07:00부터). 지수가 없는 아침·저녁 구간은
**프록시(대용 재료)로 온도를 이어서 잰다**:
- 아침(08:00~09:00): 프리마켓 **개별 종목 바스켓**(시총 상위 20~30개×시장, `dim_stock`으로 선정,
  시총 가중 등락률 = 지수 대용치) + 동시호가 예상지수(08:30~) + 간밤 미장 확정치 → **잠정 온도(basis=pre)**
- 정규장(09:00~15:30): 공식 지수 1분 → **정식 온도(basis=live)**, 15:52 확정(basis=eod)
- 저녁(15:40~20:00): 애프터마켓 **개별 종목 바스켓**(아침과 동일) + 미 지수선물 → **잠정 온도(basis=after)**
- 프록시는 **개별 종목 바스켓으로 확정**(2026-09-04, ETF 안 — NXT 거래 불확실로 버림). 덤: 바스켓 내
  상승/하락 종목 수가 공짜로 나옴 → 나중에 2층(폭)의 아침 재료.
- 프록시 잠정치는 확신도를 낮게 — 신중한 모델은 live/eod만 골라 읽으면 됨.
- 아침 프록시 온도 vs 실제 개장 후 온도를 자동 채점(프록시 품질도 측정 대상 — §6 측정 원칙).
- **확인 필요(구현 전)**: ① KIS API가 NXT 시세·예상지수를 주는지 ② 여러 종목을 한 번에 받는
  묶음 시세 TR이 있는지(없으면 바스켓 20~30종목×1분 호출량이 KIS 한도에 걸리는지 계산).

## 확정 — 판정 파라미터 v1 (2026-09-12)
"1층·2층" 같은 층 용어는 대화에서 혼동을 줘서 안 쓴다 — 그냥 **파라미터 목록**이다(만드는 순서만
있을 뿐, 모델은 층을 모르고 표준 출력 한 줄만 읽는다). 전부 결정적 계산(LLM 금지).

**방향(상승/횡보/하락) 판정** — 지수에서:
1. 지수 종가 vs 20일 이동평균 **위치**(위/아래)
2. 20일 이동평균 **기울기**(오름/내림)
3. 최근 5일 **누적 등락률**
- 규칙: ①②가 둘 다 위쪽=상승, 둘 다 아래쪽=하락, 엇갈리면=횡보.
  깜빡임 방지: 평균선 ±0.5% 안쪽은 이전 판정 유지(버퍼값은 백필 측정으로 조정).
- 확신도: 평균선에서 떨어진 거리 + 상태 지속일수.

**열(차분/달아오름/과열) 판정** — 지수에서:
4. **일중 진폭**(고가~저가 폭 / 종가, 최근 5일 평균)
5. **움직임 속도**(5일 누적 등락률의 절대값)
6. **거래대금 배율**(20일 평균 대비)
- 정규화: 각 지표를 **그 시장의 과거 1년 분포 백분위(0~100)** 로 환산. 시장마다 "평소"가 달라서
  (코스닥은 원래 코스피보다 출렁임) 고정 임계 대신 백분위 — 8개 시장에 같은 엔진 재사용 가능.
- 규칙(초안): 백분위 종합 70 미만=차분 / 70~90=달아오름 / 90 초과=과열(경계값은 백필로 조정).

**폭(breadth) 판정** — 업종 대장주 바스켓에서 (2026-09-12 순번 당김, 첫 버전부터 포함):
7. **21개 업종(sector_l1)별 시총 대장주 1개씩** → 상승/하락 개수 + 시장 전체와 역행하는 업종 목록.
- 왜 첫 버전부터: 지수만 보면 "삼성전자 혼자 급락"과 "시장 전체 패닉(21개 전부 하락)"이 같은 -2%로
  보인다. 역행 정보로 "다 내리는데 반도체 대장만 오름 = 시장 하락 속 반도체 강세" 같은 상태가 구분됨.
- 수집은 아침·저녁 프록시 바스켓과 같은 파이프라인(`raw_market_snapshot`) — 추가 비용 거의 없음.
  ※ 시총 상위 20~30개(지수 흉내용)와 업종 대장주 21개(폭 측정용)는 목적이 달라 **별도 선정**, 같은 표에 쌓음.

**시야 역할 분담(2026-09-12 재편 — 기존 "3지평 같은 공식·창만 다르게" 계획을 대체)**:
- **실시간(장중 1분)** = 사다리 상태 판정 — 매수 판단·급락 대응용. **먼저 설계·구축(이번 차례)**.
- **주 단위** = 분위기(무드)만 제시(예: "변동성 높음", "조용한 횡보") — **매도 로직의 태도를 결정**
  (변동성 높음이면 깐깐 모드: 익절 빨리·손절 바짝 / 조용하면 느긋 모드). 어휘·규칙은 재설계 예정.
- **월 단위** = 보류(재고민).

**표준화 원칙(2026-09-12 확정)**: 모델을 정교/단순으로 **구분하지 않는다** — 모든 모델이 똑같은
표준 한 줄을 읽는다. 이름표("대공황급 패닉", "건강한 상승장", "시장 하락 속 반도체 강세"…)는
칸들의 조합에서 **상태 모듈이 한 번만 파생해 같은 줄에 저장**한다(모델마다 제각각 파생하면 표준이
깨짐 — 파생 규칙도 버전 관리). ← 기존 "이름표 저장 안 함" 결정을 이렇게 변경.

### 마트 3단 구조 (2026-09-12 확정 — 예측모델도 마트의 교체 단위)
```
[1] 파라미터 계산(공용 인프라, 딱 하나)  →  state_params
[2] 예측모델들(마트 단위, 여러 개 공존)  →  state_market_temp (model_id로 구분)
[3] 매매모델들(마트 단위, 예측모델을 "구독")  →  order_intent
```
- **파라미터 계산은 모델이 아니다** — 한 번 계산해 저장, 모든 예측모델이 같은 입력을 읽는다.
  이유: ① 모델 간 성적 비교가 공정("입력이 달랐다" 변명 불가) ② 새 모델이 과거 파라미터
  기록으로 바로 개발·검증 가능.
- 규칙 기반 판정(아래 v1 규칙)은 특별한 게 아니라 **마트 1호 예측모델**(`rule-temp-v1`)이다.
  측정 기준선(무작위 판정, "내일=오늘")도 각각 모델로 등록해 같은 표에 쓴다 — 기준선을 못 이기면
  운이라는 게 순위표에서 바로 드러남(§6 측정 원칙).
- 매매모델은 설정에 **구독할 예측모델의 model_id**를 가진다. 교체 = 나란히 돌려 라이브 성적
  비교 후 구독 변경.
- 마트 명부는 `dim_model`(model_id, 종류[예측/매매], 이름, 버전, 상태, 공개 여부).

### 뱉는 말 — 단일 상태값 (어휘 v2, 2026-09-13 — 꼬리표 방식 폐기, 사용자 지시)
상태는 **하나만** 나온다. 여러 조건이 동시에 맞으면 **우선순위 높은 것 하나**로 판정
(예: 급락 조건이 맞으면 반도체가 오르고 있어도 상태는 "급락" — 급락과 테마주상승은 공존하지 않음.
테마주상승은 완만한 하락 속 역행일 때의 상태다).

**시야 1차 구분(2026-09-13 확정)**: **실시간** = 당일 매매전략에 즉각 영향(아래 표), 그중
crash(급락)는 **긴급 등급**(판정 즉시 반응 대상 — GUI·알림에서 긴급 취급) /
**주간** = 태도 무드 + **대공황 같은 국면값**("하루 내려갔다고 대공황이 아니다" — 여러 날
지속돼야 하는 상태는 주간 소속, 2026-09-13 사용자 확정. 어휘·조건은 주간 설계 때) / 월간 = 보류.

**배경(bg)** = 아침 1회 고정: ma_gap(전일 종가 vs 20일 이평 %) +1% 초과 & ma_slope(이평의
5일 변화율) > 0 → **위** / −1% 미만 & < 0 → **아래** / 엇갈리거나 ±1% 안 → **중립**.
(gap=현재 위치·빠름, slope=관성·둔함 — 둘의 엇갈림이 전환 구간을 잡는 장치. 20일은 "거래일
한 달" 관례 — 창 크기도 백필 때 10/20/30 비교 튜닝 대상.)

### 실시간 어휘 v3 — 5개로 재편 (2026-09-13, "~장(국면) 단어는 전부 주간으로")

## 주간 판정 설계 (2026-09-14~ 진행 중)
실시간(오늘의 단면 → 매매모델·슬롯 결정)과 달리 주간은 **최근 일주일의 시장 성격 → 매매로직 결정**. scope='w'.
조건식은 사용자와 하나씩 합의한 것만 "확정", 나머지는 "초안".

### 확정 (2026-09-14~15 사용자) — 최신 기준으로 정리
- **역할**: **실시간 → 매매모델 선택·슬롯값 결정 / 주간 → 매매로직 결정**. 예: 상승장 = 적극 매매 /
  하락장 = 확실한 건에만 매매 / 변동장 = 수익 나면 빠르게 팔고, 급락하는 매물을 산다.
  설계 순서 = **매매로직 목록 → 로직마다 이름표 하나 → 이름표 조건**(방향성 점검으로 바로잡음).
- **모델은 숫자를 안 본다**: 매매모델은 **이름표 하나를 input으로 받아 정해진 동작**만 한다 → 이름표가 자급자족.
- **저장 = 이름표 한 칸(state_code)**. 방향·변동성 등 계산값은 판정 근거로 `metrics`에만(2026-09-14 "두 칸 저장"을 대체 —
  DB 칸 추가 불필요, 실시간과 같은 단일 상태값).
- **갱신 = 실시간**(2026-09-15 정정): 운영에서는 주간도 일일(실시간)과 똑같이 **장중 실시간으로 재판정**한다
  (창 = 지금 시점까지 최근 5거래일). "매일 밤 판정"은 운영 전 개발·과거 검증에서 일봉으로 근사할 때만 쓰는 방식.
  주 1회 고정은 기각.
- **고정 금지**: "발동 후 N일 유지" 같은 상황값 고정은 쓰지 않는다 — 오른 날은 오른 것, 사실과 어긋난 값 금지.
  **긴급 → 하락장**처럼 매 판정마다 사실대로 다시 계산한 결과가 이어지는 건 괜찮다.
- **깜빡임 허용**: 문턱 근처에서 이름표(=매매로직)가 자주 바뀌어도 된다. 버퍼·확인 규칙 없음.
- **긴급(대공황급)**: 10년에 한두 번 있을까 말까 한 긴급상황, 기준점은 2026 이란 전쟁급 충격. **크기 기준**(원인 무관 —
  전쟁 발발일만큼 무너지면 긴급, 2026 3월 전쟁 + 6~7월 AI·반도체 폭락 해당). **주간 소속** — 실시간 갱신이라 장중
  발생 즉시 반영. 원인 기준(외부 충격만)은 뉴스 모듈 후 — pending #13. 긴 과거 데이터 재검증 보류 — pending #12.
- **시장 분석의 목적**: 온도를 **정확하게 체크**하거나 예측모델용 **파라미터를 잘 전달**하거나. **돈이 되는지는 모델이 결정**
  → 수익·미래 적중 채점은 검증 잣대가 아니다. 사람이 만든 정답지도 쓰지 않는다(검수 불가·순환).
  검증 = 계산 검산(미래 참조 없음)·사건 반영·실데이터와 뉴스로 사례 확인.
- **문구**: '깐깐/느긋 모드' 폐기 → '변동성 높음/보통'. 기준은 실데이터로 가정→검토를 반복해 뽑는다.
- **과제 정리**: 원래 과제 중 '매도 태도 무드'는 이름표→매매로직에 흡수, '실시간과의 조합 규칙'은 매매 설계(model_module) 몫.

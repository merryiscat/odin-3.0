# 화면 작업 절차 (odin_gui)

2026-09-15 클래스 충돌 사고(`sub` 중복 → 레이아웃 붕괴가 검증을 통과) 후 만든 강제 절차.
브레인 CLAUDE.md §9 "화면 작업 철칙"의 실행 버전이다. 순서대로, 생략 없이.

## 1. 고치기 전

- **새 클래스·id 이름은 먼저 충돌 검색**: 그 파일 안에서 `Grep`으로 같은 이름(부분 일치 포함)이
  이미 쓰이는지 확인. 있으면 다른 이름을 쓴다. (사고 사례: `.sub`가 등락률 글씨용으로 이미 존재)
- 디자인 판단은 `odin_gui/DESIGN.md`("Koyfin 문법")를 따른다. 이모지 금지, 데이터색 한국 관례(상승 빨강/하락 파랑).

## 2. 고친 뒤 — 자가검증 (보고 전 필수)

- **개정 번호 올리기**: `<body data-rev="rN">` 숫자를 +1. **내부 확인용으로만** — 검수 캡처의
  body 속성이나 evaluate로 대조한다. ⚠️ **사용자에게 "r4" 같은 코드를 절대 말하지 않는다**
  (글로벌 지침: 화면·보고 문구에 등급표기·코드 금지 — 2026-09-16 지적받음). 보고는
  "반영했습니다 — 새로고침(Ctrl+F5)하면 보입니다"로만.
- 헤드리스 검증 3종 (`python -m http.server`로 로컬 서버를 띄워 playwright MCP로, file://은 막힘):
  1. **콘솔 에러 0건** (간이 서버의 favicon 404는 무시)
  2. **바뀐 요소의 기하 확인**: getComputedStyle + getBoundingClientRect로 보임·크기·**형제와의 상대 위치**
     (세로로 쌓여야 할 것이 가로로 눕지 않았는지 — x·y 좌표를 실제로 비교)까지 확인. "보인다"만으로는 부족.
  3. **바뀐 영역을 요소 단위로 스크린샷** 찍어 직접 눈으로 확인. 전체 축소 스크린샷으로 대충 보지 말 것
     (축소 육안 판단이 틀린 전례 → 의심되면 픽셀 샘플링). 사이드바를 고쳤으면 사이드바를 찍는다.
- 검증 끝나면 서버 종료 + 스크린샷·`.playwright-mcp/` 삭제 (커밋에 섞이면 안 됨).

## 3. 보고

- **첫 줄에 개정 번호**: "지금 rN입니다 — 새로고침(Ctrl+F5)하면 보입니다."
- 검수(디자인 피드백) 모드는 클릭을 요소 선택으로 가로챈다 — 링크·버튼이 "안 눌린다"는 지적이 오면
  버그 취급 전에 이걸 먼저 안내.
- 창을 띄우는 명령(브라우저 열기 등)은 샌드박스 밖에서 실행.

## 4. 커밋

- 검수가 일단락됐을 때 사용자 확인 후 묶어서. 공개 레포 — 비밀값·design_refs 커밋 금지.

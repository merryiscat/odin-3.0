마켓 — 판매·업로드 (M2) — 화면 4안

목적 만든 모델을 올리고 → 검증(규격·안전 자동 검사 + 과거 데이터 백테스트)을 통과시키고 → 판매에 내놓는다. 올리는 통로 2개: LLM이 만들어 MCP로 올림 / 코드 모듈 직접 업로드.
진입점 마켓 → 탭 "판매" (M1 구매 목록에서 탭 전환).
다음 검증 통과 + 판매 시작 → M1 구매 목록에 노출 · 반려 → 같은 화면에서 검증 리포트 확인 후 재업로드.
가정 로그인 + 판매자. 모델 코드는 증권 키·주문 권한에 접근 불가(자동 검사 대상). 실행 위치 미정(보류 #14) · 과금 방식 미정(보류 #15) → {가격} 토큰. 판매 개시는 자본시장법 검토(보류 #5) 뒤.

의도

4안 공통: 성적은 판매자가 입력하지 않는다 — 오딘 검증(공통 데이터 백테스트)이 채운다. 판매자가 고를 수 있는 건 이름·설명·가격뿐. 자동 검사에 "증권 키 접근 없음 · 외부 전송 없음 · 직접 주문 없음"을 고정 — 남이 만든 코드가 돈과 키를 못 만지게(실행 모듈 하드가드와 같은 선). "미래 데이터 참조 검사"를 별도 항목으로 — 2026-09-14 오딘 자체 시뮬레이션에서도 실제로 발생한 오류라 판매 모델엔 필수. 보편 A는 첫 업로드 흐름, 보편 B는 여러 모델 운영, 실험 A는 LLM·MCP 제작 통로가 주인공, 실험 B는 구매자 시선.

대안

화면 안에서 LLM과 대화하며 모델을 만드는 내장 채팅 — 확정안이 "외부에서 만들어 올림"이라 제외. 판매자가 자기 백테스트 결과를 첨부하는 안 — 조작 가능성 때문에 제외(오딘 검증 결과만 노출). 실험 A(관제)를 보편 B(관리판)의 "새 모델 올리기" 안쪽 화면으로 넣는 혼합안.

미정

모델 규격 4종 입출력(자동 검사의 기준 자체). 백테스트 기간·비용 가정·통과 기준(기준선 대비 몇 이상이면 판매 가능?). MCP 도구 목록과 호출 한도. 반려 후 재검증 비용·횟수 제한. 버전 올릴 때 기존 구매자 처리. 판매 시작 버튼의 활성 조건(자본시장법 검토 보류 #5 전까지 비활성 고정 여부). 가격 입력 방식(보류 #15). 실행 위치(보류 #14).

의도

판매 관리와 새 모델 올리기를 한 화면에 — 올리는 동안에도 내 모델 목록이 왼쪽에 줄어든 채 남아, 올리는 모델이 그 목록의 한 줄("올리는 중" → "검증 중" → "검증 통과")로 자리 잡는 과정이 보인다. 올리기 흐름은 4안의 보류안을 조합: 단계 표시(보편 A) + LLM·MCP 통로와 승인 대기(실험 A) + 구매 목록 카드 미리보기(실험 B). 모델은 화면에서 만들지 않는다 — 사용자의 LLM이 밖에서 만들어 MCP로 보내면 "승인 대기"에 쌓이고, 사람이 골라 올린다(업로드는 항상 사람 승인). 코드 파일 통로는 규격 문서·예제와 함께. 성적은 판매자가 쓸 수 없고 검증이 채운다. 백테스트는 오래 걸리니 창을 닫아도 검증은 계속(표의 "검증 중" 행). 판매 시작은 법적 검토(보류 #5) 전까지 잠그고 "검증 통과"로 저장.

대안

보편 A 단독(올리기 전용 전체 화면 마법사) — 관리 목록과 끊겨 채택 안 함. 실험 A 단독(LLM 관제탑이 판매 탭 전체) — 코드 통로·관리 기능이 약해 ① 가져오기 칸 안으로 축소. 모델 상세 화면 — 사용자 판단으로 불필요(2026-09-15). 구매는 구매 목록 카드에서 바로.

미정

부품 4종 입출력 규격(자동 검사 기준 자체·종류 자동 판별 근거). 백테스트 기간·비용 가정·통과 기준(기준선 대비 몇 이상?). MCP 도구 목록과 호출 한도, LLM 활동 기록 화면 범위. 반려 후 재검증 비용·횟수. 버전 올릴 때 기존 구매자 처리. 가격 입력 방식(보류 #15). 실행 위치(보류 #14). 검증 끝 알림 수단(앱 알림/텔레그램).
